# Надсилання кодів через Gmail / Google Workspace

Учитель може надіслати кожному імпортованому учню окремий лист із ПІБ, назвою класу, особистим кодом, адресою ФізЛаб та інструкцією приєднання. Інші учнівські адреси у лист не додаються. Сам імпорт листів не надсилає. [Навчальний приклад листа](email-preview.html) можна відкрити у браузері.

## Підключення Gmail адміністратором

1. Для адреси відправника ввімкніть [двоетапну перевірку Google](https://myaccount.google.com/security).
2. Створіть [пароль додатка](https://myaccount.google.com/apppasswords) для ФізЛаб. Використовуйте його замість звичайного пароля Google. У Google Workspace доступність паролів додатків залежить від політики адміністратора; якщо опції немає, зверніться до адміністратора домену.
3. Додайте налаштування до локального `.env` на сервері. Пароль додатка вводьте без пробілів і не публікуйте в GitHub чи чаті.

```dotenv
SMTP_HOST="smtp.gmail.com"
SMTP_PORT="465"
SMTP_SECURE="true"
SMTP_USER="your-school-account@gmail.com"
SMTP_PASSWORD="your-16-character-app-password"
PUBLIC_APP_URL="https://your-fizlab-domain.example"
```

Значення — приклади: замініть адресу, пароль додатка та домен своїми. `SMTP_FROM` можна не задавати: відправник збігатиметься з `SMTP_USER`. Іншу адресу можна використовувати тільки як дозволений у Gmail псевдонім відправника.

`PUBLIC_APP_URL` має вести на **цей самий застосунок і базу**, доступні учням через інтернет за HTTPS. Якщо основний `APP_URL` уже є такою адресою, `PUBLIC_APP_URL` можна не задавати. Поштова кнопка недоступна без належних SMTP-налаштувань та публічної адреси. `localhost` у листі відкрив би комп’ютер самого учня, тому така адреса не підтримується.

При публічному розгортанні також налаштуйте основний `APP_URL` на адресу сайту й `COOKIE_SECURE=true` відповідно до README. Просте додавання домену до `.env` не публікує локальний сервер. Поки сайт працює тільки на комп’ютері вчителя, коди можна передавати вручну; доступ із інтернету потрібно налаштувати окремо.

TLS і перевірка сертифіката ввімкнені. Для іншого SMTP-сервісу на порту 587 задайте `SMTP_SECURE="false"`: у такому режимі STARTTLS обов’язковий. Не вимикайте перевірку сертифікатів.

## Дії вчителя

1. Імпортуйте список з колонками `ПІБ;Email` у потрібний клас.
2. У блоці очікування натисніть **«Надіслати коди на Email»**.
3. Оберіть адресатів вручну або кнопкою «Обрати доступних».
4. Перевірте список і натисніть «Надіслати листи (N)».
5. Залишайте сторінку відкритою до завершення. Застосунок обробляє невеликі порції по п’ять листів і показує прогрес. Якщо жоден лист у порції не прийнято й є помилки, розсилка зупиняється для перевірки налаштувань та адрес.

Записи без Email та учні, які вже приєдналися, пропускаються. Пошта й адресати доступні тільки вчителю — власнику класу. Облікові записи й паролі учнів не створюються: новий учень обирає роль «Учень / учениця» та вводить особистий код при реєстрації зі своєю адресою. Учень із наявним акаунтом входить і вводить код у розділі «Мій клас».

## Статуси й повторні спроби

- **Ще не надсилали** — спроби ще не було.
- **Надсилається** — обробка триває; одночасне натискання в іншій вкладці не створить ще одну спробу.
- **Передано пошті** — SMTP-сервер прийняв лист. Це не підтвердження доставки чи прочитання. Попросіть учня також перевірити «Спам».
- **Не надіслано** — отримано відмову або встановлено, що надсилання не почалося. Перевірте поштові налаштування, адресу та обмеження Gmail.
- **Потребує перевірки** — з’єднання перервалося без однозначного результату, або обробка перервалася понад дві хвилини тому. Лист міг бути прийнятий; спочатку перевірте його наявність у відправника та одержувача.

За замовчуванням прийняті поштою листи й невизначені спроби повторно не обираються. Для повтору ввімкніть «Дозволити повторне надсилання вибраним учням», оберіть потрібні адреси та натисніть кнопку надсилання. Код не змінюється. Між спробами потрібна щонайменше хвилина; після перерваної активної спроби — дві. Гарантувати відсутність дубліката після обриву SMTP неможливо, тому повтор потребує явної дії вчителя.

Статуси зберігаються в базі та залишаються після оновлення сторінки. Після закриття сторінки ненадіслані порції не продовжуються автоматично: відкрийте клас, оновіть статус і оберіть залишок. Gmail / Workspace мають власні ліміти надсилання; застосунок не обходить ці обмеження. Вбудоване обмеження — до 500 адресатів за 15 хвилин на вчителя, повтори та пропущені запити також використовують ліміт.

## Оновлення на Windows

Зупиніть сервер, зробіть резервну копію бази за README, замініть файли проєкту, зберігши `.env`, і виконайте:

```powershell
cd "H:\Solovey Danil fizika 2026\Redmi-main\Redmi-main"
npm ci
docker compose up -d db
npm run db:generate
npm run db:migrate
npm run dev
```

Міграція `202610260002_invitation_email` додає лише облік поштових спроб до запрошень. Наявні учні, коди, відповіді та оцінки зберігаються. Для Docker-версії виконайте `docker compose up --build -d`: міграція застосовується автоматично, SMTP-змінні передаються контейнеру з `.env`.

## Перевірка без реальних листів

`npm test` перевіряє шаблон, екранування HTML, конфігурацію та розрізнення відмови й невизначеного результату. `npm run test:e2e` використовує тільки витратну базу `_test` і локальний TLS SMTP-сервер, який нікуди не пересилає листи. Для тестового сертифіката потрібен OpenSSL; сертифікат створюється тимчасово, перевірка TLS не вимикається. Реальні SMTP-значення середовища замінюються тестовими.
