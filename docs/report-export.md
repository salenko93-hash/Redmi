# Окреме збереження PDF і друк

У верхній панелі лабораторного зошита, перегляду шаблону та перевірки роботи вчителем є дві незалежні кнопки:

- **Зберегти PDF** створює файл `FizLab-Lab-01.pdf` (номер відповідає роботі) і запускає завантаження. Діалог принтера не відкривається.
- **Друкувати** відкриває системний діалог друку. Можна вибрати принтер, сторінки й кількість копій. Скасування повертає до того самого етапу та відповідей.

На iPhone або iPad браузер може показати попередній перегляд PDF: збережіть його через меню поширення → **Зберегти у Файли**. Це поведінка браузера, окрема від кнопки друку.

## Вміст звіту

Експортуються всі чотири етапи, незалежно від відкритого етапу зошита:

1. Назва й номер роботи, учень, клас, статус, режим досліду та наявні оцінка й відгук.
2. Підготовка: мета, обладнання, теорія, методичні уточнення та прогноз.
3. Експерименти: інструкції, таблиці з одиницями, побудовані графіки й збережені покази віртуальних моделей.
4. Контрольні запитання з рисунками та відповідями, схеми сил із числовими значеннями, усі частини висновку, творче завдання й коментарі вчителя.

Беруться поточні відповіді в браузері, включно з чернеткою, яку ще не встигло зберегти автозбереження. Експорт не здає роботу, не змінює оцінку та не замінює серверне збереження. Порожні відповіді позначено тире; статус чернетки зберігається.

PDF містить український шрифт Roboto, текст, який можна виділяти, та таблиці з переносом рядків і пагінацією A4. Рисунки й графіки переносяться з поточного SVG у зображення потрійної роздільності. Текст довгих відповідей не обмежено висотою полів введення. Калькулятор, навігація, кнопки, модальні збільшення та робоча анімація приладу у звіт не входять.

У перегляді шаблону ПІБ і клас позначені як незазначені. У призначеній роботі вони беруться з поточного користувача й класу, у перевірці вчителем — з учнівського звіту та списку класу.

## Технічні умови

PDF генерується в браузері; відповіді не надсилаються стороннім сервісам. Бібліотеки та вбудовані шрифти завантажуються із самого застосунку при першому експорті. На сервері не потрібні Chromium, LibreOffice або окремий сервіс PDF. Нова міграція бази для цієї функції не потрібна.

Додано залежності `pdfmake` та `html-to-pdfmake`. Після отримання нових файлів збережіть свій `.env`, зупиніть старий сервер і виконайте `npm ci`. Для розробки запустіть `npm run dev`, для сервера — `npm run build && npm start`. Якщо оновлення також містить раніше не встановлені функції, застосуйте наявні міграції стандартною командою `npm run db:migrate` після резервного копіювання бази.

Ця гілка базується на збереженому варіанті `2d3f4b2`. Позначка `baseline-learning-progress-2026-10-28` та окрема гілка прогнозів і порівнянь залишаються доступними.

## Перевірка

`tests/e2e/report-export.spec.ts` завантажує PDF усіх десяти робіт і перевіряє український текст, усі розділи та рисунки. Окремий сценарій перевіряє довгу відповідь до останнього рядка, актуальну чернетку, ПІБ і клас, друк A4, повернення фокуса та етапу, мобільні кнопки, оцінку й відгук учителя.

Для перевірки PDF у тестовому середовищі потрібен `pdftotext` з Poppler; для звичайного використання застосунку він не потрібен. Тести працюють лише з окремою тестовою базою.
