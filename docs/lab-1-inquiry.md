# Перша робота: дослідження з доказами

Новий загальнодоступний шаблон має назву **«Середня швидкість руху · дослідження з доказами»**. Він створюється як окрема версія. Початковий шаблон, версії вчителів, уже призначені роботи, відповіді та оцінки зберігаються. На сторінці першої роботи прибрано блок редактора та службове пояснення версії. Попередній шаблон залишається доступним через раніше збережену адресу або призначену роботу.

## Навчальна послідовність

1. **Проблемне запитання.** Чи однакова середня швидкість кульки на різних відстанях від сталого старту за незмінного нахилу? Учень записує прогноз із поясненням.
2. **План перевірки.** Чотири короткі відповіді: яку величину змінюю; що зберігаю сталим і чому; що, чим і як вимірюю; який результат змусить переглянути прогноз. Кнопка **«Зафіксувати прогноз і план»** зберігає копію для подальшого порівняння. Поточні формулювання можна уточнювати, збережена копія залишається видимою. Це навчальний запис учня, а не перевірка того, коли він насправді сформував думку.
3. **Вимірювання й докази.** Основні три рядки відповідають різним шляхам. Секундомір керує рухом; час і розрахунки учень вводить сам. Після таблиці потрібно зіставити щонайменше два числові результати, розглянути інші причини відмінностей та описати спосіб перевірки сумнівів. Якщо повторити дослід неможливо, це можна пояснити в полі перевірки.
4. **Повторна перевірка за можливості.** Додатковий блок містить один сталий шлях і три ручні вимірювання часу. Він допомагає відрізнити три умови від трьох повторів однієї умови. Основна таблиця залишається окремою. Середній час і розкид можна обчислити самостійно та пояснити їх використання. Якщо блок використано, при здаванні перевіряються додатні шлях і всі три значення часу; повністю порожній блок необов’язковий.
5. **Висновок.** Твердження → числові докази → пояснення зв’язку → межі висновку. Учень бачить збережений прогноз і пояснює, чому залишає або уточнює свою думку, а також пропонує наступну перевірку.

Усі ці відповіді входять до автозбереження, локальної чернетки, історії спроб, перевірки вчителя, PDF та друку. Перевірка заповнення в новій версії охоплює нові поля; для старих версій правила здавання залишаються попередніми.

## Оцінювання вчителем

Залишається шкала 12 балів: чотири критерії по 0–3. У новій версії це план і контроль умов; вимірювання, обчислення й одиниці; докази та альтернативні пояснення; висновок і перегляд думки. Для кожного критерію є пояснення. Учитель може залишити адресний коментар до плану, доказів і перегляду прогнозу та повернути роботу на доопрацювання.

Початковий помилковий прогноз не є підставою автоматично знижувати оцінку. Обґрунтоване уточнення після перевірки — цінний результат. Арифметична перевірка допомагає перевіряти формули; зміст аргументів оцінює вчитель. Бали не визначаються автоматично за довжиною тексту чи натисканнями кнопок.

У додатковому творчому завданні перевіряється твердження про важчу кульку. Потрібно зберігати шлях, нахил і діаметр та порівнювати умови з опором і без нього. Важливо обговорити, чи можна побачити невелику різницю ручним секундоміром. Висновок про модель не можна без перевірки переносити на будь-яке реальне обладнання.

## Установлення оновлення на Windows

Збережіть `.env` та резервну копію бази за чинною інструкцією адміністратора. Замініть файли проєкту, зупиніть попередній сервер через Ctrl+C, у папці з `package.json` виконайте:

```powershell
cd "H:\Solovey Danil fizika 2026\Redmi-main\Redmi-main"
docker compose up -d db
npm run db:seed
npm run dev
```

Нові залежності або міграція схеми для цієї зміни не потрібні. Звичайний `db:seed` додає новий шаблон і не перезаписує наявні версії. Повторний запуск не створює ще одну копію шаблону. Номер нової версії обирається після вже наявних, тому власна версія вчителя не замінюється.

Після Ctrl+F5 відкрийте бібліотеку, виберіть **«Середня швидкість руху · дослідження з доказами»** й натисніть **«Спробувати як учень»**. Для учнів призначте класу саме нову версію. Старе призначення автоматично не перемикається на нову методику. Призначена робота виконується в режимі, який обрав учитель: реальне обладнання, модель або надані дані.

Під час запуску через стандартний Dockerfile додавання шаблону виконує наявна команда запуску `db:seed`.
