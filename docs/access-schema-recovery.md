# Відновлення сумісності старої схеми доступу

Підтверджена стара структура: User.removedAt; Membership.isActive та Membership.removedAt. Контрольна сума виконаної міграції 202610280001_access_lifecycle: 21f9685be8adac7c89ac5d9aee55ef64b513f3f9d8bf91fef0bd40a38ed8a918. Поточний SQL-файл має SHA-256 518c90dc914d3eeaf755a65bc9b5474aace196170167259a0f99d28559b0aa3c та інші поля. Це різні версії схеми, а не просто перенесення рядків Windows.

Пакет додає вузьку сумісність тільки для цієї пари контрольних сум і перевіреної структури. Старий запис у _fizlab_migrations не переписується. Окрема транзакційна міграція 202610280002_reconcile_access_lifecycle додає відсутні поля:

- User.removedAt → User.deletedAt; видалений користувач залишається неактивним.
- Membership.removedAt не порожнє → LEFT.
- Інакше Membership.isActive = true → ACTIVE, false або NULL → SUSPENDED.

Старі колонки залишаються для звірки. Паролі, коди відновлення, ідентифікатори, ролі, класи, роботи, оцінки, спроби й коментарі не видаляються. Поля, які вже існують у поточній схемі, не перезаписуються зі старих колонок; повторний запуск не скасовує пізнішого відновлення доступу. Інші незбіги контрольних сум, змінений файл переходу або невідома структура блокують виконання.

## Застосування на Windows PowerShell 7

1. Зупиніть сервер Ctrl+C.
2. Розпакуйте файли пакета без додаткової батьківської папки в корінь наявного проєкту, де лежить package.json. Погодьтеся замінити scripts/migrate.ts і однойменні файли пакета. Пакет не містить .env, бази, node_modules чи облікових записів.
3. Увійдіть у папку проєкту. Створіть резервну копію та запустіть перехід:

```powershell
cd "H:\Solovey Danil fizika 2026\Redmi-main\Redmi-main"
$fizlabBackup = "fizlab-before-repair-" + (Get-Date -Format "yyyyMMdd-HHmmss") + ".dump"
docker compose exec -T db pg_dump -U fizlab -d fizlab -Fc > $fizlabBackup
if ($LASTEXITCODE -eq 0) {
    npm run db:migrate && npm run db:generate && npm run build && npm start
}
```

Це команда для локальної PostgreSQL у db-сервісі цього проєкту. PowerShell 7.6 зберігає двійковий формат pg_dump під час перенаправлення. За помилки копіювання чи міграції не переходьте до запуску застосунку. Копію .dump зберігайте приватно, поза публічними файлами.

Очікуваний результат:

```text
202610280001_access_lifecycle: recognized legacy version; original checksum preserved
202610280002_reconcile_access_lifecycle: applied
```

Після наступного запуску друга міграція матиме статус already applied. За потреби діагностика: `npm exec -- tsx scripts/db-doctor.ts`.

## Перевірки

Відтворено стару структуру та записану контрольну суму з наданого звіту. Перевірено активних, призупинених і вибулих учнів; видаленого вчителя; збереження пароля й коду відновлення; незмінні класи, звіти, оцінки, спроби й коментарі; повторний запуск після відновлення доступу; відмову для невідомої контрольної суми чи невідомої структури. Перевірені також нова установка й поточна схема. Перевірено також часові позначки з часовим поясом зі збереженням UTC-часу. Пройшли сім цільових інтеграційних/браузерних сценаріїв та перевірка типів.
