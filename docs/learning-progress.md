# Навчальний поступ

У верхній навігації відкрийте **Навчальний поступ**. Учитель вибирає власний клас і учня; учень бачить свої роботи в активних класах. Посилання також є у класі та на сторінці перевірки звіту. Учитель може переглядати історію вибулих учнів свого класу.

## Початок роботи

На сторінці призначеної роботи під калькулятором є панель **Мій навчальний поступ**. Запис дій початково вимкнено. Учень натискає **Увімкнути запис навчальних дій** для конкретного призначення. Згода не потрібна для виконання або здавання роботи. Використання цієї функції слід пояснити учням і узгодити з правилами закладу щодо навчальних даних.

Записуються лише:

- запуск, завершення, пауза та явне скидання віртуального приладу;
- числові параметри завершеного віртуального запуску;
- перенесення показів у таблицю та натискання запиту допомоги;
- виправлення розрахунку, підтверджене сервером під час збереження відповідей.

Натискання клавіш, вміст буфера обміну, активність інших вкладок, камера, мікрофон, IP-адреса та тривалість роботи у цьому журналі не зберігаються. Навчальні події не надсилаються зовнішнім сервісам або мовним моделям. Події надходять із браузера і не доводять фактичного виконання досліду.

Бібліотека, вебпам’ятки, пробне проходження та перегляд учителем не створюють подій. У призначеній реальній роботі журнал може описувати лише тренування з віртуальним приладом; виконання фізичного досліду він не підтверджує.

## Правила версії 1.0

Модель показує чотири напрями без загального балу, рейтингу, психологічних типів або автоматичних змін оцінки:

| Напрям      | Підстава спостереження                                                                 | Межа висновку                                                                                                     |
| ----------- | -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Планування  | Наявність прогнозу; порівняння параметрів послідовних завершених запусків однієї серії | Заповнений прогноз не доводить, що його зробили до досліду. Кілька змін можуть відповідати методиці.              |
| Вимірювання | Заповнені поля; повтори з однаковими параметрами                                       | Наявність показів не доводить точності. Повтор детермінованої моделі не вимірює випадкову похибку.                |
| Обчислення  | Узгодженість арифметики з введеними даними; підтверджені виправлення                   | Виправлення рахується лише зі сталими числовими вхідними даними; заповнення порожньої клітинки не є виправленням. |
| Висновки    | Заповнення чотирьох частин висновку                                                    | Зміст, фізичний сенс і відповідність прогнозу перевіряє вчитель.                                                  |

Учень у режимі самостійної роботи не отримує деталі перевірки арифметики до оцінювання. Учитель бачить їх у своїх класах. Запити допомоги, паузи й скидання не трактуються як слабкість або порушення. Для кожної роботи є спостереження та наступний навчальний крок; між різними темами не обчислюється спільна «здатність» учня.

Старі звіти доступні для опису заповнення та арифметики. Історія запусків заднім числом не вигадується. У вимкненому журналі показано **лише збережені відповіді**.

## Надійність і керування даними

Події синхронізуються пакетами кожні 5 секунд, після відновлення інтернету та перед здаванням. Повтор пакета не дублює події. До 100 очікуваних подій зберігаються лише в пам’яті вкладки; закриття або навігація до синхронізації може їх втратити. Це не змінює окреме локальне збереження відповідей. За помилки журналу показано повідомлення і кнопку повторної синхронізації. Максимум — 2000 подій на учня в одному призначенні; досягнення межі не блокує дослід або здавання.

**Вимкнути й видалити журнал** припиняє запис і видаляє події саме цієї роботи. Відповіді, спроби, оцінки та коментарі залишаються. Серверний блокувальний ключ узгоджує видалення з пакетами подій та виправленнями, щоб пізній пакет не відновив вимкнений журнал. Учень не може створювати серверні події виправлення через API або вказувати іншого власника журналу.

У спостереження включаються лише події, отримані сервером за останні 180 днів. Старі події видаляються при читанні журналу, відкритті огляду або записі нових подій. Для регулярного фізичного видалення й за відсутності відвідувань налаштуйте щоденний запуск у планувальнику сервера:

```sh
npm run learning:prune
```

Звіти та оцінки цією командою не видаляються. Якщо школа встановлює інший строк зберігання, змініть `LEARNING_RETENTION_DAYS` у `lib/learning-progress.ts` і відповідні тексти інтерфейсу та документації.

## Оновлення

Нова міграція `202610280003_learning_progress` створює дві окремі таблиці. Наявні міграції, облікові записи, звіти й оцінки не переписуються. Перед оновленням створіть резервну копію бази. На Windows після отримання цієї версії файлів зупиніть старий сервер та виконайте:

```powershell
cd "H:\Solovey Danil fizika 2026\Redmi-main\Redmi-main"
npm run db:migrate && npm run db:generate && npm run build && npm start
```

Для розробки після міграції й генерації можна виконати `npm run dev`. Відкрийте `/progress` з облікового запису вчителя або учня. Для збору нових спостережень учневі потрібно увімкнути журнал у призначеній роботі й провести дослід.

Модульні тести перевіряють правила, обмеження подій і всі десять шаблонів. Браузерні тести перевіряють справжній прилад, права доступу, серверні виправлення, режим самостійної роботи, мобільний огляд, видалення журналу зі збереженням звіту та видалення старих подій.
