# Діагностика невідповідності міграцій

Помилка `Applied migration ... changed` означає, що SHA-256 локального SQL-файлу відрізняється від записаного в `_fizlab_migrations`. Саме повторення збірки не змінює структуру бази. Помилка Prisma P2022 під час читання сесії з приєднаним користувачем може вказувати на відсутню колонку користувача; назва Session у трасуванні не визначає точну колонку.

Виконайте `npm run db:doctor` у папці проєкту. Якщо оновлено лише файл команди, а не package.json, використайте `npm exec -- tsx scripts/db-doctor.ts`.

Команда використовує DATABASE_URL із наявного `.env` та транзакцію READ ONLY. Виводяться лише метадані: відсутні за поточним Prisma Client колонки, незбіги контрольних сум, визначення нових полів та обмежень керування доступом. Дані користувачів, URL підключення та паролі не друкуються; записи й контрольні суми не переписуються. Перевірка `formattingOnly` розпізнає LF/CRLF та BOM, але не дозволяє автоматично ігнорувати змінений SQL.

Для міграції `202610280001_access_lifecycle` звіт також порівнює файл з незмінним опублікованим SHA-256 `518c90dc914d3eeaf755a65bc9b5474aace196170167259a0f99d28559b0aa3c`. Якщо локальний файл інший, потрібне зіставлення його вмісту й історії, а не скидання бази або видалення запису про виконану міграцію.

Перевірено на окремій тимчасовій тестовій базі: правильна схема; відсутня User.deletedAt і невідомий записаний хеш; різниця тільки LF/CRLF. Після всіх перевірок записи журналу та синтетичні приватні дані залишилися незмінними й не потрапили до виводу. Тимчасову базу видалено після тесту. На основній базі підтверджено режим READ ONLY та відсутність невідповідностей.
