# Адмінка для команди з чотирьох учителів

Один із чотирьох учителів може одночасно бути адміністратором. Він працює зі своїми класами у звичайному кабінеті та має додатковий розділ «Адміністрування». Решта вчителів користуються окремими обліковими записами.

Адмінка керує запрошеннями й доступом учителів, показує стан бази, навчальних шаблонів і пошти та останні 30 адміністративних дій. Адміністратор отримує відомості про склад команди й кількість класів. Чужі учнівські звіти, оцінки, списки та коди класів залишаються доступними їхнім учителям.

## Оновлення на Windows

Зупиніть сервер Ctrl+C. Зробіть резервну копію бази, замініть файли проєкту новою версією, зберігши власний `.env`. Docker Desktop має працювати. У PowerShell:

```powershell
cd "H:\Solovey Danil fizika 2026\Redmi-main\Redmi-main"
npm ci
docker compose up -d db
npm run db:generate
npm run db:migrate
```

Міграція `202610270001_admin` додає облік доступів і журнал. Наявні користувачі залишаються активними, класи, відповіді та оцінки зберігаються. Жоден користувач не стає адміністратором автоматично.

## Перший адміністратор

Потрібен уже зареєстрований активний учитель. Якщо такого облікового запису немає, виконайте `npm run teacher:invite`, передайте одноразовий код першому вчителю та завершіть його реєстрацію.

Оператор сервера надає цьому вчителю додатковий доступ:

```powershell
npm run admin:grant -- --email "teacher@school.example"
npm run dev
```

Замініть адресу на фактичну адресу свого облікового запису. Команда не створює користувача чи пароля і не змінює роль учня на вчителя. Для вже активного адміністратора повторний запуск нічого не змінює. Надання прав записується у журнал як дія оператора сервера.

Після входу або оновлення сторінки в меню з’явиться «Адміністрування». Для запуску всього застосунку у Docker оновіть його командою `docker compose up --build -d`, а права надайте через `docker compose exec app npm run admin:grant -- --email "teacher@school.example"`.

## Запрошення трьох колег

1. Відкрийте «Адміністрування».
2. Укажіть Email колеги та натисніть «Створити запрошення».
3. Скопіюйте показаний код і передайте колезі особисто. Код показується лише один раз; у базі зберігається його хеш.
4. Колега натискає «Зареєструватися», обирає «Учитель», реєструється саме з указаною адресою, задає власний пароль і вводить код у видимому обов’язковому полі запрошення вчителя.
5. Повторіть для двох інших учителів.

Код діє 24 години й використовується один раз. Неправильна адреса не витрачає запрошення. Чинне невикористане запрошення можна відкликати; після цього код не діє. Якщо код загублено, відкличте попереднє запрошення й створіть нове. Для вже зареєстрованого користувача повторне запрошення не створюється.

Запрошення не надсилаються автоматично. Розсилка кодів учням працює окремо через [Gmail / SMTP](gmail-invitations.md).

## Призупинення й відновлення доступу

У таблиці вчителів натисніть «Призупинити». Після завершення дії всі сеанси цього вчителя скасовані, новий вхід заборонений. Класи, призначення та учнівські роботи зберігаються.

Кнопка «Відновити» повертає можливість входу. Учитель входить заново зі своїм паролем; старі сеанси не відновлюються. Паролі користувачів в адмінці не показуються й не задаються. Для забутого пароля є наявне відновлення за особистим резервним кодом.

Змінити власний доступ у вебадмінці не можна. Додаткового адміністратора може призначити оператор сервера командою `admin:grant`. Одночасні дії не можуть залишити систему без активного адміністратора.

## Якщо загублено пароль і особистий код

Оператор запускає команду на комп’ютері, де розміщено базу застосунку. Потрібен доступ до папки проєкту та його `.env`. Для власного облікового запису на Windows:

```powershell
cd "H:\Solovey Danil fizika 2026\Redmi-main\Redmi-main"
npm run account:recover -- --email "teacher@school.example"
```

Команда перевипускає особистий резервний код для наявного активного користувача. Скопіюйте код із PowerShell, на сторінці входу виберіть «Забули пароль?», введіть пошту, код і власний новий пароль (10–128 символів). Після завершення сайт покаже наступний резервний код — збережіть його. Якщо сайт пропонує увійти зі збереженим паролем браузера, замініть його новим.

Ролі, права адміністратора, класи та роботи не змінюються. Старий резервний код і всі попередні сеанси скасовуються. До введення нового пароля на сайті сам пароль не змінюється. Код одноразовий, його незашифрований текст показано лише в терміналі після успішної операції; у базі зберігається хеш. Кодів і паролів немає в журналі дій. Команда не створює користувача й не знімає призупинення доступу.

Якщо користувача немає, перевірте адресу й `.env`: робоча база на Windows відрізняється від тестової чи хмарної. Не реєструйте дублікат, якщо потрібні дані наявного облікового запису. Міграція бази та нові залежності для команди не потрібні.

## Якщо форма відновлення не відкривається

Публічна сторінка входу не приховується за загальним клієнтським екраном завантаження. Внутрішні розділи зберігають свої індикатори. Посилання «Забули пароль?» веде на `/?mode=recover`: форма відкривається сервером навіть до завантаження JavaScript. Для виконання відновлення потрібен завантажений застосунок. Якщо браузер відкрив `localhost`, а в `.env` налаштовано адресу локальної мережі, сторінка покаже посилання на правильну адресу. У режимі розробки Next.js допускає свої ресурси для `localhost`, `127.0.0.1` і точного хоста з `APP_URL`. Після зміни `.env` перезапустіть сервер. Захист запитів за `APP_URL` залишається чинним; на ПК та телефоні користуйтеся цією адресою.

Якщо оновлюєте проєкт копіюванням файлів із ZIP поверх старої папки, приберіть застарілий файл `app/loading.tsx`: індикатор перенесено в `components/page-loading.tsx` та внутрішні розділи. Після копіювання всіх нових файлів виконайте з папки проєкту `Remove-Item .\app\loading.tsx -ErrorAction SilentlyContinue`. При оновленні через Git файл видаляється автоматично.

Оператор може одразу змінити пароль на своєму ПК, минаючи форму:

```powershell
cd "H:\Solovey Danil fizika 2026\Redmi-main\Redmi-main"
npm run account:recover -- --email "teacher@school.example" --set-password
```

Введіть новий пароль двічі та натисніть Enter після кожного введення. Символи навмисно не відображаються. Потрібно 10–128 символів; за невідповідності повторного введення жодних змін не буде. Пароль не передається в аргументах командного рядка, не виводиться й не потрапляє в журнал операцій. Після успіху увійдіть зі своїм новим паролем, а виведений новий резервний код збережіть окремо. Старі код і сеанси скасовані; дані й права залишаються.

Для автоматизації зі сховищем секретів є прапорець `--set-password --password-stdin`; він читає один пароль зі стандартного вводу, без підтвердження. Не передавайте пароль аргументом чи змінною середовища. Інтерактивному користувачу цей прапорець не потрібний.

## Пошта й стан системи

Адмінка показує доступність бази, кількість базових шаблонів, адресу відправника та адресу сайту у листах. «Перевірити підключення пошти» перевіряє TLS-з’єднання й авторизацію без надсилання листів. Успіх такої перевірки не підтверджує доставку майбутніх листів.

Поштовий пароль задається оператором сервера у `.env` за інструкцією Gmail; вебадмінка його не показує й не змінює. Якщо пошту або публічну адресу ще не налаштовано, кнопка перевірки недоступна.

Журнал містить надання прав, створення й відкликання запрошень, зміни доступу та результати перевірки пошти. У нього не записуються паролі, коди запрошень чи тексти учнівських відповідей.

Копіювання та відновлення виконує оператор сервера за [інструкцією README](../README.md#резервне-копіювання). Адмінка містить посилання на інструкцію; автоматичного розкладу резервних копій і відновлення бази через браузер у цій версії немає.

Копії містять учнівські дані. Зберігайте їх поза публічними папками та репозиторієм, з обмеженим доступом. Перед оновленнями робіть копію, а відновлення перевіряйте в окремій базі. Не видаляйте Docker volume з робочою базою.

## Реєстрація за ролями

На формі «Зареєструватися» потрібно явно обрати «Учитель» або «Учень / учениця». Вхід для наявних користувачів залишається спільним: пошта й пароль.

- Для вчителя видиме обов’язкове поле «Код запрошення вчителя». Підходить лише одноразовий чинний код адміністратора з відповідною адресою. Успішна реєстрація додає вчителя до команди й прибирає запрошення з очікування.
- Для учня видиме обов’язкове поле «Особистий код учня». Учитель отримує ці коди після імпорту списку в класі та передає їх учням. Перевіряється особисте запрошення зі списку та його Email, якщо він заданий. Код адміністратора й загальний код класу для цього поля не підходять. Обліковий запис, використання коду та членство у класі створюються однією транзакцією.
- Помилкова роль, чужа адреса або недійсний код не витрачають запрошення й не створюють новий акаунт. Права адміністратора через реєстрацію отримати неможливо.

Для сумісності зі старими клієнтами API без поля `role` зберігає попередній шлях звичайної учнівської реєстрації й учительську реєстрацію з перевіреним `invite`. Чинне запрошення вчителя на цю адресу блокує випадкове створення учнівського акаунту і на цьому шляху. Нова форма завжди передає явну роль; жоден із кодів не дає прав іншої ролі.

Нова форма реєстрації не змінює ролі наявних акаунтів автоматично. Якщо колега раніше зареєструвався як учень, адміністратор може явно надати йому роль учителя за інструкцією нижче.

Перевірено: 76 модульних і 29 браузерних сценаріїв, окремо повторено три сценарії пошти та імпорту після оновлення підказок; успішні перевірка типів і production-збірка. У запущеній версії перевірено обидві ролі, обов’язкові поля, спільний вхід і ширини 320–1440 px без помилок браузера. Кількість користувачів, членств і звітів робочої бази збережена.

## Копіювання коду в локальній мережі

Кнопка «Скопіювати запрошення» копіює код учителя й показує результат поруч із кнопкою. На HTTPS або localhost використовується Clipboard API. На локальній HTTP-адресі, де цього API немає, або після відмови браузера використовується резервна команда копіювання з виділеного поля. Якщо браузер блокує обидва способи, поле залишається виділеним: на комп’ютері натисніть Ctrl+C, на телефоні утримуйте поле й оберіть «Скопіювати». Зберігайте отриманий код приватно.

Перевірено справжній вміст буфера в Chromium для основного способу, відсутнього API та відмови в дозволі; окремо перевірено ручне виділення без хибного повідомлення про успіх. Пройшли 76 модульних тестів і три браузерні сценарії: копіювання, адміністрування та реєстрація за ролями.

## Якщо колега вже зареєструвався як учень

1. В адмінці у блоці «Запросити колегу» введіть його наявну пошту й натисніть «Створити запрошення».
2. Замість повторного запрошення для активного учнівського акаунту з’явиться блок із його ім’ям та поштою. Перевірте, що це саме ваш колега.
3. Позначте «Підтверджую, що це обліковий запис учителя» й натисніть «Надати роль учителя». «Скасувати» не змінює акаунт.
4. Користувач з’явиться в команді; йому потрібно ввійти знову зі своєю поштою та попереднім паролем. Повторна реєстрація й нове запрошення не потрібні.

Права адміністратора ця дія не надає. Ідентифікатор акаунту, пароль, код відновлення, членства й звіти зберігаються. Після зміни користувач бачить інтерфейс учителя; попередні учнівські дані залишаються в базі. Старі сесії відкликаються, невикористані запрошення вчителя на цю пошту прибираються з очікування. Дія записується до журналу адміністратора. Призупинений акаунт спершу потребує перевірки оператором; роль і доступ не змінюються автоматично.

Перевірено збереження ідентифікатора, хешів пароля й відновлення, членств та повного вмісту звітів; повторний вхід зі старим паролем, відкликання старих сесій, очищення запрошення й один запис журналу. API відхиляє учня, звичайного вчителя, неавторизованого користувача, запит без належного Origin, відсутнє підтвердження, чужу пару id/Email, призупинений або вже вчительський акаунт. Пройшли 76 модульних та чотири цільові браузерні сценарії, після фінального фокусування повторено сценарій виправлення ролі; успішні перевірка типів та production-збірка.

## Призупинення, видалення та відновлення

У «Команді вчителів» призупинення та відновлення доступу є оборотними. «Видалити» після підтвердження остаточно видаляє обліковий запис із бази разом із сеансами, особистими відповідями, коментарями та запрошеннями вчителя. Його класи, учнівські роботи й авторські шаблони переходять адміністратору, який виконав видалення. Учнівські акаунти не видаляються. Пошта звільняється: адміністратор може створити нове запрошення, за яким людина зареєструє новий акаунт із новим паролем і кодом відновлення. Старі запрошення для цієї пошти більше не діють; новий акаунт не отримує старих класів чи прав адміністратора. Раніше архівовані акаунти з позначкою «Видалено з команди» можна видалити остаточно тією самою кнопкою. Власний акаунт видалити не можна; система зберігає принаймні одного активного адміністратора.

У списку «Учні класу» його вчитель має дії «Призупинити», «Відновити» та «Видалити — учень вибув». Вибуття стосується лише цього класу: інші класи й обліковий запис залишаються доступними. Відповіді, спроби та оцінки зберігаються в журналі й у списку робіт класу. Припинений доступ не можна обійти повторним введенням коду класу або вже використаного особистого коду; відновлення виконує вчитель. Кількість активних учнів та прогрес у кабінеті не враховують вибулих і призупинених.

Оновлення потребує `npm run db:generate` і `npm run db:migrate` перед запуском сервера. Нова міграція лише додає поля стану та не видаляє наявні дані.

Реєстрація має обов’язкове поле «Повторіть пароль». Обидва значення мають збігатися; перемикач «Показати пароль / Приховати пароль» змінює видимість обох полів. Перемикач також доступний при вході та відновленні пароля.
