# Адмінка для команди з чотирьох учителів

Один із чотирьох учителів може одночасно бути адміністратором. Він працює зі своїми класами у звичайному кабінеті та має додатковий розділ «Адміністрування». Решта вчителів користуються окремими обліковими записами.

Адмінка керує запрошеннями й доступом учителів, показує стан бази, навчальних шаблонів і пошти та останні 30 адміністративних дій. Адміністратор отримує відомості про склад команди й кількість класів. Чужі учнівські звіти, оцінки, списки та коди класів залишаються доступними їхнім учителям.

## Оновлення на Windows

Зупиніть сервер Ctrl+C. Зробіть резервну копію бази, замініть файли проєкту новою версією, зберігши власний `.env`. Docker Desktop має працювати. У PowerShell:

```powershell
cd "H:\Solovey Danil fizika 2026\Redmi-main\Redmi-main"
npm ci
docker compose up -d db
npm run db:generate
npm run db:migrate
```

Міграція `202610270001_admin` додає облік доступів і журнал. Наявні користувачі залишаються активними, класи, відповіді та оцінки зберігаються. Жоден користувач не стає адміністратором автоматично.

## Перший адміністратор

Потрібен уже зареєстрований активний учитель. Якщо такого облікового запису немає, виконайте `npm run teacher:invite`, передайте одноразовий код першому вчителю та завершіть його реєстрацію.

Оператор сервера надає цьому вчителю додатковий доступ:

```powershell
npm run admin:grant -- --email "teacher@school.example"
npm run dev
```

Замініть адресу на фактичну адресу свого облікового запису. Команда не створює користувача чи пароля і не змінює роль учня на вчителя. Для вже активного адміністратора повторний запуск нічого не змінює. Надання прав записується у журнал як дія оператора сервера.

Після входу або оновлення сторінки в меню з’явиться «Адміністрування». Для запуску всього застосунку у Docker оновіть його командою `docker compose up --build -d`, а права надайте через `docker compose exec app npm run admin:grant -- --email "teacher@school.example"`.

## Запрошення трьох колег

1. Відкрийте «Адміністрування».
2. Укажіть Email колеги та натисніть «Створити запрошення».
3. Скопіюйте показаний код і передайте колезі особисто. Код показується лише один раз; у базі зберігається його хеш.
4. Колега реєструється саме з указаною адресою, задає власний пароль і вводить код у полі запрошення вчителя.
5. Повторіть для двох інших учителів.

Код діє 24 години й використовується один раз. Неправильна адреса не витрачає запрошення. Чинне невикористане запрошення можна відкликати; після цього код не діє. Якщо код загублено, відкличте попереднє запрошення й створіть нове. Для вже зареєстрованого користувача повторне запрошення не створюється.

Запрошення не надсилаються автоматично. Розсилка кодів учням працює окремо через [Gmail / SMTP](gmail-invitations.md).

## Призупинення й відновлення доступу

У таблиці вчителів натисніть «Призупинити». Після завершення дії всі сеанси цього вчителя скасовані, новий вхід заборонений. Класи, призначення та учнівські роботи зберігаються.

Кнопка «Відновити» повертає можливість входу. Учитель входить заново зі своїм паролем; старі сеанси не відновлюються. Паролі користувачів в адмінці не показуються й не задаються. Для забутого пароля є наявне відновлення за особистим резервним кодом.

Змінити власний доступ у вебадмінці не можна. Додаткового адміністратора може призначити оператор сервера командою `admin:grant`. Одночасні дії не можуть залишити систему без активного адміністратора.

## Якщо загублено пароль і особистий код

Оператор запускає команду на комп’ютері, де розміщено базу застосунку. Потрібен доступ до папки проєкту та його `.env`. Для власного облікового запису на Windows:

```powershell
cd "H:\Solovey Danil fizika 2026\Redmi-main\Redmi-main"
npm run account:recover -- --email "salenko93@gmail.com"
```

Команда перевипускає особистий резервний код для наявного активного користувача. Скопіюйте код із PowerShell, на сторінці входу виберіть «Забули пароль?», введіть пошту, код і власний новий пароль (10–128 символів). Після завершення сайт покаже наступний резервний код — збережіть його. Якщо сайт пропонує увійти зі збереженим паролем браузера, замініть його новим.

Ролі, права адміністратора, класи та роботи не змінюються. Старий резервний код і всі попередні сеанси скасовуються. До введення нового пароля на сайті сам пароль не змінюється. Код одноразовий, його незашифрований текст показано лише в терміналі після успішної операції; у базі зберігається хеш. Кодів і паролів немає в журналі дій. Команда не створює користувача й не знімає призупинення доступу.

Якщо користувача немає, перевірте адресу й `.env`: робоча база на Windows відрізняється від тестової чи хмарної. Не реєструйте дублікат, якщо потрібні дані наявного облікового запису. Міграція бази та нові залежності для команди не потрібні.

## Пошта й стан системи

Адмінка показує доступність бази, кількість базових шаблонів, адресу відправника та адресу сайту у листах. «Перевірити підключення пошти» перевіряє TLS-з’єднання й авторизацію без надсилання листів. Успіх такої перевірки не підтверджує доставку майбутніх листів.

Поштовий пароль задається оператором сервера у `.env` за інструкцією Gmail; вебадмінка його не показує й не змінює. Якщо пошту або публічну адресу ще не налаштовано, кнопка перевірки недоступна.

Журнал містить надання прав, створення й відкликання запрошень, зміни доступу та результати перевірки пошти. У нього не записуються паролі, коди запрошень чи тексти учнівських відповідей.

## Резервні копії

Копіювання та відновлення виконує оператор сервера за [інструкцією README](../README.md#резервне-копіювання). Адмінка містить посилання на інструкцію; автоматичного розкладу резервних копій і відновлення бази через браузер у цій версії немає.

Копії містять учнівські дані. Зберігайте їх поза публічними папками та репозиторієм, з обмеженим доступом. Перед оновленнями робіть копію, а відновлення перевіряйте в окремій базі. Не видаляйте Docker volume з робочою базою.
