# ФізЛаб

Вебзастосунок українською для виконання й перевірки 10 лабораторних робіт із фізики. Next.js 16, React 19, TypeScript, PostgreSQL 17, Prisma 6 із JavaScript-драйвером PostgreSQL.

## Що реалізовано

- Адмінка для команди вчителів: особисті запрошення, керування доступами, перевірка пошти, журнал дій. Один із учителів може бути адміністратором. [Налаштування](docs/admin.md).
- Учнівські облікові записи; одноразові запрошення вчителів; відновлення доступу за резервним кодом без зовнішнього поштового сервісу.
- Класи та приєднання за кодом; призначення версії роботи, терміну, режиму підказок і джерела даних.
- Імпорт списків учнів із CSV UTF‑8: ПІБ та Email, попередній перегляд, перевірка помилок і повторів, особисті коди приєднання. [Інструкція для вчителя](docs/student-import.md).
- Надсилання особистих кодів через Gmail / SMTP: вибір адресатів, окремі листи, статуси та явні повторні спроби. [Підключення Gmail](docs/gmail-invitations.md).
- Усі 10 шаблонів за наданими PDF, оригінали й рисунки. Методичні уточнення явні; навчальні дані не підміняють вимірювання.
- Прогноз → експеримент → контрольні запитання → висновок; необов’язкові творчі завдання.
- Серверне автозбереження; локальна чернетка при обриві мережі; виявлення конфліктів між пристроями, експорт чернетки й відновлення серверної версії.
- Таймер і лічильник циклів; графіки за даними; умовні схеми сил; довідник густин.
- Перевірка арифметики з урахуванням округлення та десяткової коми. Учень сам вводить результат, автоматичного заповнення немає.
- Здавання, блокування редагування, коментарі до окремих відповідей, рубрика 4 × 3 бали, повернення на доопрацювання, історія спроб із незмінними відповідями.
- Особисті версії навчального тексту вчителя; зміни не змінюють уже призначені роботи та шаблони інших учителів.
- Журнал, експорт CSV, окреме завантаження PDF і друк повного звіту, адаптивний інтерфейс, маніфест для встановлення на домашній екран.

## Локальний запуск

Потрібні Node.js 24, npm, Docker із Compose. Основні функції не потребують сторонніх API-ключів. Необов’язкова поштова розсилка потребує налаштування Gmail / SMTP та публічної HTTPS-адреси сайту.

```bash
cp .env.example .env
npm ci
docker compose up -d db
npm run db:generate
npm run db:migrate
npm run db:seed -- --demo
npm run dev
```

Ті самі кроки можна відтворити командою `bash scripts/setup.sh --demo` (без `--demo` створюються лише шаблони).

Відкрийте `http://localhost:3000`. APP_URL у `.env` має точно відповідати origin браузера (протокол, домен і порт): це перевіряється для всіх змінювальних запитів.

Демонстраційні користувачі **лише для локального ознайомлення**:

| Роль    | Пошта             | Пароль       |
| ------- | ----------------- | ------------ |
| Учитель | teacher@demo.test | LabDemo2026! |
| Учень   | student@demo.test | LabDemo2026! |

Демо-клас: `7-А · Фізика`; код `FIZ7A2026`. Дані синтетичні. Звичайний `npm run db:seed` додає тільки шаблони. Прапорець `--demo` заборонений у production. Не запускайте публічний сервіс на базі з демонстраційними обліковими записами.

Для створення вчителя:

```bash
npm run teacher:invite
```

Передайте надрукований одноразовий код учителю приватним каналом. Учитель вводить його при реєстрації. Код діє 24 години. Після реєстрації потрібно зберегти окремий код відновлення облікового запису; у базі зберігається лише його хеш. Для демо-акаунтів такого коду немає, користуйтеся відомим демонстраційним паролем. Якщо пароль і код загублено, оператор може перевипустити код командою `npm run account:recover -- --email "ваша@пошта.example"`; [інструкція](docs/admin.md#якщо-загублено-пароль-і-особистий-код). Якщо форма недоступна, додайте `--set-password`: новий пароль вводиться приховано в терміналі.

## Збірка й Docker

```bash
npm run build
npm start
```

Або весь стек:

```bash
docker compose up --build -d
```

Контейнер застосунку виконує транзакційні міграції й додає шаблони, після чого запускає production-сервер. Демонстраційних користувачів він не створює.

Для реального розгортання встановіть власний сильний `POSTGRES_PASSWORD`, публічний HTTPS `APP_URL`, `COOKIE_SECURE=true`, забезпечте TLS на reverse proxy і резервне копіювання. Не використовуйте значення з `.env.example` як виробничі секрети. Для зовнішньої PostgreSQL встановіть її DATABASE_URL і налаштуйте перевірку TLS відповідно до провайдера; не вимикайте перевірку сертифікатів.

Приклади запуску з телефона у тій самій мережі: встановіть APP_URL з LAN-адресою комп’ютера, перезапустіть сервер і відкрийте ту саму адресу на телефоні. APP_URL приймає один canonical origin.

## Перевірки

```bash
npm test
npm run typecheck
npm run build
```

End-to-end тести виконуються на **окремій витратній базі**, вміст якої очищається. Для поштового сценарію потрібен OpenSSL: runner створює тимчасовий тестовий сертифікат та підміняє SMTP локальним сервером без зовнішньої розсилки. Ім’я бази мусить закінчуватися на `_test`; runner відмовляється використовувати основну базу. Потрібно спочатку створити її:

```bash
docker compose exec -T db psql -U fizlab -d postgres -c 'CREATE DATABASE fizlab_test'
# TEST_DATABASE_URL уже є в .env.example
npx playwright install chromium
npm run test:e2e
```

Якщо Chromium уже встановлено, завантаження браузера не потрібне:

```bash
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:e2e
```

Runner мігрує й очищає тільки тестову базу, додає демо-дані й запускає окремий сервер на порту 3100. Перевіряються ролі, приєднання, арифметика, заборона передчасної перевірки, конфлікти версій, здавання, повернення, повторна здача, оцінки, збереження історії, ізоляція доступу, CSRF, відновлення пароля, мобільний і настільний інтерфейс та всі 10 шаблонів. Окремі сценарії перевіряють імпорт учнів, ізоляцію класів, повторний і одночасний імпорт, прив’язку кодів до Email, одноразове приєднання, ПІБ у журналі та видалення невикористаного запрошення. Скріншоти й сліди помилок — у `test-results/`.

## База даних й міграції

Схема — `prisma/schema.prisma`. SQL-міграції — `prisma/migrations/`. `npm run db:migrate` використовує невеликий транзакційний runner на `pg`: advisory lock серіалізує застосування, SHA-256 перевіряє незмінність уже застосованих файлів, таблиця `_fizlab_migrations` обліковує версії. Повторний запуск не змінює дані. Зміни схеми оформлюйте новою SQL-міграцією; не редагуйте застосовані файли.

Використовується підтримуваний Prisma engineType `client` і `@prisma/adapter-pg`. Для генерації — WASM-конфігурація. Нативні рушії з binaries.prisma.sh не потрібні. У перевіреній версії Prisma експериментальна WASM-інтроспекція PostgreSQL має помилку десеріалізації типу `name`; тому для застосування SQL використовується власний runner, а не `prisma migrate dev/deploy`. Перевірки TLS, підписів і контрольних сум під час встановлення не вимикаються.

Основні сутності: User, Session, TeacherInvite, AdminAudit, StudentInvite, RateLimit, Classroom, Membership, LabVersion, Assignment, Submission, Attempt, Comment. Призначення прив’язане до конкретної незмінної версії. Рубрика й оцінка кожної зданої спроби зберігаються в історії.

## Резервне копіювання

Зберігайте резервні копії поза сервером із контрольованим доступом. Перед оновленням зробіть копію:

```bash
docker compose exec -T db pg_dump -U fizlab -d fizlab -Fc > fizlab-backup.dump
```

Перевіряйте відновлення в окремій порожній базі, не поверх робочої:

```bash
docker compose exec -T db psql -U fizlab -d postgres -c 'CREATE DATABASE fizlab_restore'
docker compose exec -T db pg_restore -U fizlab -d fizlab_restore --no-owner < fizlab-backup.dump
```

Після відновлення перевірте вхід і перегляд звітів, а також наявність історії спроб. Docker volume `postgres_data` зберігає базу між перезапусками контейнера; `docker compose down -v` видаляє її.

## Межі першої версії

- Є реальний експеримент, аналіз наданих даних та віртуальні моделі всіх 10 робіт. Моделювання не підтверджує навички роботи з фізичним обладнанням. Автоматичного розпізнавання відео немає.
- Редактор змінює назву, мету, теорію, запитання і творче завдання. Універсальний конструктор таблиць та нових формул не реалізовано.
- Графіки будуються з введених чисел; повного ручного редактора графіків немає. Схеми сил — навчальні й спрощені.
- Спільні групові вимірювання та завантаження учнівських фото/відео не реалізовано. Зовнішні посилання можна зазначати як джерело даних.
- Локальна чернетка підтримує обрив мережі під час відкритої роботи. Повне завантаження приватних сторінок без мережі не підтримується; service worker не кешує учнівські відповіді.
- Оцінювання текстів виконує вчитель. Коректність арифметики не підтверджує достовірність експерименту.
- Дедлайн відображається, але прострочення не блокує здавання. Це дозволяє вчителю прийняти роботу пізніше.
- Живий екран класу оновлюється при перезавантаженні; WebSocket/SSE-підписки не реалізовано.
- Для першого запуску використовуйте наявний checkout; окремий Git worktree не потрібен. Зовнішнє розгортання не виконується автоматично.

## Навчальні матеріали

Для роботи № 1 замість показу PDF доступна вебпам’ятка `/materials/1`: сучасне адаптивне оформлення, уточнена методика, формула, прилад для тренування, векторний графік і друк. Її можна відкрити на етапі підготовки або через «Вебпам’ятка до роботи». Графік у звіті також став векторним: можна виділяти проміжки часу, збільшувати його й читати дані як таблицю. Пам’ятка не зберігає відповіді; учень здає призначену роботу через наявний звіт. [Розбір помилок і методичних уточнень](docs/lab-1-review.md).

Робота № 2 має вебпам’ятку `/materials/2` зі спільним сучасним оформленням, двома формулами, відліком від нуля, серіями 10/20/30 обертів, контрольними запитаннями та уточненим творчим дослідом із колесом. Віртуальна установка має вимірювальну платформу, кріплення, проєкцію нитки, об’ємну кульку та цифровий відлік. Є об’ємний вигляд і вигляд зверху; перемикання зберігає перебіг досліду. Повзунок радіуса змінює траєкторію, секундомір показує фізичний час, а лічильник — завершені оберти. Це кінематична модель: довжина й натяг нитки не розраховуються. [Розбір роботи № 2](docs/lab-2-review.md). Тренувальні прилади у вебпам’ятках не створюють записів у журналі.

Робота № 3 має вебпам’ятку `/materials/3` із трьома вкладками дослідження A, l та m. Вимірювання довжини уточнено до центра кульки, незалежність від амплітуди обмежено малими кутами, а задачу про шлях і переміщення сформульовано для явно заданих прямолінійних коливань. У всіх трьох серіях маятник має деталізовані штатив, кріплення, нитку й об’ємну кульку, сталий масштаб довжини, окрему збільшену шкалу дугової координати та цифровий відлік повних циклів. Відтворення 1× зберігає різницю темпу для різних довжин. [Розбір роботи № 3](docs/lab-3-review.md). Перемикання вкладки скидає тренувальний прилад; відповіді зберігаються тільки в призначеній роботі.

Робота № 4 має вебпам’ятку `/materials/4`: правила рівноплечого зважування, тарування, перетворення одиниць, чотири власні рядки звіту й пояснення абсолютної та відносної похибок. Приклад 46,47 г позначений навчальним; результат для партії зернин визначений як середня маса однієї зернини. Віртуальні терези мають металеве коромисло, горизонтальні об’ємні шальки, нульову стрілку, впізнавані предмети й циліндричні та пластинчасті важки. Кількість кожного номіналу наведена явно; є кнопка очищення шальки. Замість скану задачі про 32 камінці використано векторну схему з текстовими переліками навантажень і уточненням маси мішечка. [Розбір роботи № 4](docs/lab-4-review.md).

Робота № 5 має вебпам’ятку `/materials/5` із трьома вкладками: брусок, занурення та рідина. Уточнено повне занурення, внесок тримача, віднімання тари, одиниці й межі визначення речовини за густиною. Усі три серії мають об’ємні зразки, градуйовані лінійки, прозорі мензурки й цифрові ваги; покази зручно читати також у картках на телефоні. Занурення та наливання змінюють рівень рідини, а зважування враховує ту саму посудину. Реалістичніша навчальна пляшка олії містить перевірені дані 782 г і 0,85 л. Необґрунтоване усереднення густин різних тварин замінено оцінкою об’єму неживої моделі. [Розбір роботи № 5](docs/lab-5-review.md). У роботі та вебпам’ятці є таблиця густин 52 речовин із пошуком, фільтрами й двома одиницями. В «Інструментах дослідника» всіх робіт калькулятор завжди відкритий, окремий секундомір прибрано; запуск і скидання розміщено одразу під віртуальним приладом.

Робота № 6 має вебпам’ятку `/materials/6`: пружність відокремлено від лінійності, уточнено одиниці, статичну рівновагу, розвантаження та час відновлення гуми. Прилад має об’ємний штатив, металеві кріплення, 12 витків пружини або гумовий шнур, чотири циліндричні тягарці та міліметрову лінійку 0–50 см зі спільним масштабом для l₀, l і x. Навантаження й розвантаження плавно починаються від попереднього положення; за 0 г можна перевірити повернення довжини. Покази читабельні також у картках на телефоні. Якісний графік двох пружин став векторним і доступним для збільшення. [Розбір роботи № 6](docs/lab-6-review.md).

Робота № 7 має вебпам’ятку `/materials/7`: умови рівномірного ковзання та горизонтальної тяги, розрізнення тертя спокою й ковзання, повторюваність і парне порівняння граней. У задачі про 350 г явно задано рух і вид коефіцієнта. Установка має об’ємний дерев’яний брусок, фактурні поверхні, циліндричні тягарці й прозорий механічний динамометр зі шкалою 0–5 Н та узгодженим рухом пружини й покажчика. Поворот зберігає розміри того самого бруска та горизонтальну тягу. Схема чотирьох сил має спільний масштаб, а покази читабельні в картках на телефоні. [Розбір роботи № 7](docs/lab-7-review.md).

Робота № 8 має вебпам’ятку `/materials/8`: дві вкладки для площі й навантаження, правильні одиниці площі та середній тиск. Об’ємний дерев’яний брусок зберігає розміри при повороті; латунні тягарці по 100 г стоять на його верхній грані. Міліметрові лінійки й окремий вигляд опорної грані використовують спільний масштаб. Силу явно визначено за масою; рухаються лише вказівники відліку, доступні пауза й продовження. Покази продубльовано великим текстом для телефона; площу першої серії та тиск учень обчислює сам. Екранна модель невагомості розрізняє вагу та силу тяжіння; у задачі про вантажівку явно додано кількість контактів, а оцінку ходьби уточнено як змінні F(t) і S(t). [Розбір роботи № 8](docs/lab-8-review.md).

Робота № 9 має вебпам’ятку `/materials/9`: два стани одного зразка, прозорі динамометри 0–10 Н з поділкою 0,2 Н, рухомою пружиною та сталою довжиною нитки. Скляну посудину підіймає ножичний столик; рівень води, занурення й натяг узгоджені зі збереженням об’єму рідини. Є пауза/продовження та великі покази для телефона. Густину й матеріал учень визначає самостійно; цифрові значення моделі не задають точності реального приладу. [Розбір роботи № 9](docs/lab-9-review.md).

Робота № 10 має вебпам’ятку `/materials/10`: середня густина всієї закритої системи, повний і занурений об’єми, рух та спокій на дні, нейтральність і плавання на поверхні. Прозора пробірка з корком змінює розміри за V; рівень піску відповідає його об’єму, а повзунок обмежено місткістю. Рівень води узгоджений із витісненим об’ємом; занурення враховує заокруглене дно, схема сил додає реакцію опори лише після контакту. Є пауза/продовження й великі покази для телефона. Рисунок трьох тіл має об’ємні грані, виділення і збільшення. [Розбір роботи № 10](docs/lab-10-review.md).

Оригінали десяти наданих PDF збережено як джерела у `public/originals/`; сторінки з рисунками — у `public/references/`. Усі десять робіт мають вебпам’ятки `/materials/1`–`/materials/10` замість PDF-посилань у навчальному маршруті. Адаптовані структуровані шаблони — `lib/labs.ts`. Оновлення вихідного шаблону не переписує існуючі версії завдань у базі; нові вебпам’ятки містять уточнення й доступні також зі старих призначень. Перед застосуванням на уроці вчитель має переглянути методичні уточнення, критерії та відповідність своїй навчальній програмі.

## Якщо на Windows сторінка постійно завантажується

Успішні `db:migrate` та `db:seed -- --demo` означають, що база налаштована. Запускайте сервер командою `npm run dev` і відкривайте `http://localhost:3000`. Параметри `--host` та `--strictPort` належать іншим інструментам і не підтримуються Next.js. Порт у браузері має відповідати фактичному запуску та APP_URL.

Для перевірки PostgreSQL: `docker compose exec -T db pg_isready -U fizlab`. Після оновлення застосунку endpoint `/api/health` повертає `{"status":"ok"}`, якщо база й десять базових шаблонів доступні, або HTTP 503 без розкриття налаштувань. Час установлення з’єднання обмежений 5 секундами, виконання запиту — 10 секундами.

Якщо база працює, але dev-сервер зависає під час компіляції, зупиніть його Ctrl+C та спробуйте `npm run build`, потім `npm start`. Не запускайте dev і production одночасно на одному порту. Збережіть останні повідомлення PowerShell для діагностики.

## Віртуальні лабораторії

Основна навігація розташована зверху. У всіх десяти роботах сцена й керування стоять поруч: запуск, пауза, скидання, точні числові поля, повзунки та перенесення показів — праворуч. «Розгорнути» збільшує робочий простір зі збереженням стану; Escape повертає звичайний вигляд. На телефоні панелі адаптуються до ширини екрана. [Опис інтерфейсу](docs/experiment-interface.md).

У кожній із десяти робіт на етапі «Експеримент» доступний інтерактивний прилад. У роботах № 3, 5 та 8 окремі прилади відповідають окремим серіям; разом — 15 сценаріїв. Прилади працюють мишею, клавіатурою й сенсорним екраном. Є запуск, пауза, продовження та скидання. Для користувачів зі зменшеними анімаціями прилад переходить до кінцевого стану без руху.

Учитель обирає «Віртуальний експеримент» під час призначення або змінює режим на сторінці класу до здавання чи першого перенесення модельних показів. Старі призначення не переводяться у віртуальний режим автоматично. У реальному режимі й бібліотеці прилади доступні для тренування, без перенесення у звіт.

Учень змінює параметри, запускає дослід, обирає рядок таблиці та підтверджує перенесення. Переносяться тільки вимірювані покази; розрахункові поля цього рядка очищаються для нового самостійного розрахунку. Дані позначено як модельні, параметри й покази залишаються у звіті та історії спроб. Якщо учень потім змінить виміряну клітинку вручну, це видно у деталях перенесення. Самостійна робота не показує готових розрахункових відповідей.

Сервер перевіряє дозволений режим, межі параметрів і відповідність показів моделі. У віртуальному режимі для здавання потрібен перенесений дослід у кожному рядку. Це перевірка узгодженості синтетичних даних, а не доказ виконання фізичного експерименту чи неможливості списування.

Моделі детерміновані, без штучної випадкової похибки. Анімація може бути прискореною, а час приладу — фізичний час моделі. На кожному приладі наведено рівняння й припущення. Для шнура є нелінійна оборотна модель гуми та лінійна модель пружини; для плавання розрізняються потопання, нейтральна плавучість і рівновага на поверхні. Солона вода — творче дослідження; її покази не переносяться в таблицю досліду зі звичайною водою. Формули та межі реалізовано в `lib/simulation.ts`.

У роботі № 1 прилад показано як жолоб на штативі над горизонтальним столом. Є сталева та пластмасова (поліпропілен) суцільні кульки, діаметр 10–50 мм і маса за формулою m = ρπd³/6. Мітки показують обертання; розмір кульки на схемі збільшено у 4 рази для наочності. [Модель і пояснення](docs/ramp-balls.md). Довжина шкали жолоба й лінійки стала — 2 м, поділка — 0,1 м; після шкали є сталий технічний запас для упору. Лівий повзунок змінює нахил, піднімаючи кріплення на штативі; правий задає шлях 0,2–2 м, пересуваючи фінішний упор відносно сталого старту. Золотиста ділянка показує вибраний шлях; написи «Старт» та «Фініш» завжди горизонтальні. Керування розташоване зліва і справа також на телефоні. Після зміни параметрів попередній запуск скидається; запустіть дослід знову, щоб отримати нові покази часу. Під час руху параметри заблоковані; натисніть «Пауза» або «Скинути прилад», щоб змінити їх. Для нових запусків доступні умови «У повітрі» з опором (модель v2) та ідеальні умови (v1); збережені старі досліди лишаються ідеальними.

Для оновлення на Windows зупиніть сервер Ctrl+C, скопіюйте файли свіжого ZIP у чинну папку проєкту із заміною та збережіть локальний `.env`. Оновлення з імпортом учнів потребує міграції: виконайте `npm run db:generate`, потім `npm run db:migrate` і `npm run dev`. Наявні відповіді зберігаються; не видаляйте Docker volume з даними.

## Перегляд шаблону та пробне проходження

У бібліотеці є помітний банер «Перегляд шаблону — відповіді не зберігаються». Учитель може натиснути «Спробувати як учень»: відповіді, схеми й перенесені віртуальні покази існують лише у пам’яті відкритої сторінки, без запитів збереження, локальних чернеток та записів у журналі. Повернення до шаблону чи оновлення сторінки скидає спробу. Учень виконує призначені роботи через «Мій простір».

Рисунки розміщені біля відповідних контрольних запитань, без паперової сітки та повторного тексту. У роботі № 1 це інтерактивний векторний графік, у № 4 — векторна схема терезів із текстовими навантаженнями; у № 5 — векторна етикетка олії з читабельними даними, у № 6 — якісний векторний графік пружин, у № 10 — векторний рисунок трьох плаваючих тіл. Кнопка збільшення відкриває доступний модальний перегляд із закриттям кнопкою або Escape. Для всіх робіт № 1–10 посилання ведуть на вебпам’ятки; PDF збережено як архівні джерела. Зміни тексту запитань учителем не перезаписуються: рисунок показується тільки для відповідної за змістом умови.

У схемах сил нульові вектори приховано, незаповнені схеми позначено явно. Ненульова сила тяжіння спрямована вниз, виштовхувальна сила та реакція горизонтальної опори — вгору. Масштаб спільний для всіх трьох схем, значення явно підписані умовними одиницями; наявні збережені числа не переінтерпретуються як ньютони. Опора показується у першій схемі після додавання реакції опори. Для кількісних висновків потрібні власні розрахунки у ньютонах.

Для версії з імпортом учнів застосуйте нову міграцію за [інструкцією оновлення](docs/student-import.md#оновлення-на-windows). Повторно створювати облікові записи чи запускати демо-заповнення не потрібно.

Реєстрація має явний вибір ролі: «Учитель» вводить код адміністратора, «Учень / учениця» — особистий код зі списку свого вчителя. Учень одразу приєднується до класу. Коди різних ролей не взаємозамінні; запрошення з Email перевіряє відповідність пошти. Для наявних акаунтів вхід залишається за поштою та паролем. [Докладніше](docs/admin.md#реєстрація-за-ролями).

Керування доступом: адміністратор відновлює, призупиняє або видаляє вчителя з команди зі збереженням історії; вчитель виконує ці дії для учня лише у власному класі. Видалені вчителі й вибулі учні мають окремі списки для відновлення. Повторне введення коду не обходить призупинення. Після цього оновлення потрібна міграція `202610280001_access_lifecycle` — перед нею створіть резервну копію бази. [Адміністрування](docs/admin.md#дії-у-команді-вчителів) · [Учні](docs/student-import.md#якщо-учень-вибув-або-потрібно-призупинити-доступ).

Оформлення: п’ять тем — Лісова, Океан, Лаванда, Сонячна та Троянда. Перемикач є на сторінці входу та в меню профілю; великі картки — у «Мій обліковий запис». Вибір зберігається в цьому браузері, не змінює оформлення інших користувачів і не скидає дослід. [Опис тем](docs/color-themes.md).

Якщо `db:migrate` повідомляє `Applied migration ... changed`, запустіть `npm run db:doctor`: це діагностика лише на читання без виведення паролів або учнівських даних. Успішна збірка не виправляє незастосовану схему. [Діагностика бази](docs/database-diagnostics.md).

Для старої версії керування доступом з `User.removedAt` та `Membership.isActive/removedAt` додано міграцію-перехід зі збереженням даних і початкової контрольної суми. [Інструкція відновлення](docs/access-schema-recovery.md).

Навчальний поступ: чотири напрями — планування, вимірювання, обчислення та висновки. Учитель переглядає спостереження за власними класами, учень — свої роботи й наступні кроки. Запис навчальних дій добровільний для кожної роботи; вимкнення видаляє журнал зі збереженням звітів та оцінок. Потрібна нова міграція `202610280003_learning_progress`. [Як увімкнути, правила й керування даними](docs/learning-progress.md).

Звіт має дві окремі дії: **Зберегти PDF** завантажує готовий файл, **Друкувати** відкриває діалог принтера. Обидві дії охоплюють усі етапи, таблиці, рисунки та довгі відповіді незалежно від відкритого етапу зошита. [Експорт і друк](docs/report-export.md).
